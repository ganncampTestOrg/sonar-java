This rule raises an issue when the ScopedValue.Carrier returned by ScopedValue.where() is neither run nor returned.

Why is this an issue?

ScopedValue.where() does not bind a value by itself. It returns a ScopedValue.Carrier, and the binding only takes effect while the run() or call() method of that carrier is executing. If the carrier is dropped, the call to where() has no effect and the scoped value stays unbound, which usually leads to a NoSuchElementException or to the wrong value being read.

How to fix it

Call run() or call() on the carrier, or pass the carrier to code that does. If the call to where() is not needed, remove it.

Code examples

Noncompliant code example

ScopedValue.where(USER, "alice"); // Noncompliant
doWork();

Compliant solution

ScopedValue.where(USER, "alice").run(() -> doWork());
